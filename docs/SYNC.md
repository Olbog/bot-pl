(`docs/SYNC.md`): после записи — скопировать во второй проект.

## S-001. Неверный `TELEGRAM_TOKEN` → `getUpdates: Not Found`

- **Где найдено:** bot-en, первый запуск на сервере, 2026-10-19.
- **Симптом:** в логе `setMyCommands: Not Found`, затем каждые 5 с `getUpdates: Not Found`; Gemini при этом работает
  («Цепочка моделей: …» в логе есть). Бот не отвечает.
- **Причина:** в `TELEGRAM_TOKEN` попал не токен Telegram (вставили ключ Gemini, `AQ.…`). Telegram на неверный токен
  отвечает 404 Not Found.
- **Решение:** токен от @BotFather — всегда `цифры:буквы`, длина 44–47. Взять заново: @BotFather → `/mybots` → бот →
  API Token. Ключ Gemini в `.env` бота вообще не нужен — он только в секретах Worker'а.
- **Реализация:** код не менялся. Диагностика без показа токена:
  ```powershell
  docker compose exec bot python -c "import os; t=os.environ['TELEGRAM_TOKEN']; print('длина', len(t), '| начало', repr(t[:4]), '| конец', repr(t[-3:]), '| двоеточие:', ':' in t)"
  $t = ((Get-Content .env | Select-String '^TELEGRAM_TOKEN=').ToString() -split '=',2)[1].Trim()
  Invoke-RestMethod "https://api.telegram.org/bot$t/getMe"     # ok: True — токен рабочий
  ```
- **Идея на потом (оба бота):** при старте проверять `getMe` и писать в лог понятное «неверный TELEGRAM_TOKEN»
  вместо бесконечных `Not Found`. ❓

## S-004. Один Worker на два бота — общая квота Gemini

- **Суть:** лимиты Gemini — на проект Google Cloud, не на ключ. Пока bot-en ходит через Worker bot-pl, они делят квоту,
  и длинные ответы B1 тратят её быстрее.
- **Решение:** ключ Gemini **в новом проекте** → копия Worker'а со своим `PROXY_TOKEN` → новые `WORKER_URL` /
  `PROXY_TOKEN` в `.env` bot-en → `docker compose up -d`. Пошагово — `BACKLOG.md`, задача с высоким приоритетом.
- **bot-pl:** менять ничего не нужно, он остаётся на своём Worker'е.
- **Сделано 2026-10-21:** Worker `gemini-proxy-en` (копия кода bot-pl, секреты с теми же именами, новые значения:
  ключ Gemini из нового проекта, свой `PROXY_TOKEN`), `.env` bot-en переключён, `docker compose up -d`; в Metrics
  нового Worker'а — запросы бота, ошибок 0. Платного биллинга в Google нет. Общим остаётся только аккаунт Cloudflare
  (бесплатно 100 000 запросов в сутки на все Worker'ы — с запасом).
- **Как проверить, что квоты раздельные:** AI Studio → API keys → у ключей двух ботов разные проекты (колонка Project);
  Cloudflare → Worker → Metrics — запросы идут в «свой» Worker.
- **Переименование 2026-10-21:** Worker bot-pl `gemini-proxy` → `gemini-proxy-pl`. Адрес workers.dev строится из имени,
  поэтому старый перестаёт работать: в `.env` bot-pl новый `WORKER_URL` + `docker compose up -d` (не `restart`).
  Итог: `gemini-proxy-pl` — bot-pl, `gemini-proxy-en` — bot-en; так же записано в `.env.example` обоих проектов.

## S-014. ⭐ 📂 Своя тема в меню «В словарь» + 🤖 «Разложить «Разное» по темам»

- **Где:** bot-pl, 2026-10-21, по запросу Марка (дополнение к S-011).
- **Зачем:** не всегда хочется доверять теме от ИИ — собрать «свой набор» из слов разных тем; плюс после S-011 весь
  старый словарь лежит в «⭐ Разное N», раскидывать вручную долго.
- **Как работает:**
  - в меню «⭐ В словарь» строка «📂 Куда: 🤖 темы подберёт ИИ» и кнопка «📂 Тема: 🤖 авто» → экран выбора:
    🤖 Авто / 🗂 любая существующая тема / ✍️ Новая тема (текстом) / ⬅️ Назад. Выбрана тема — всё отмеченное
    (и «✍️ Свои слова» из этого меню) ложится туда, запрос к модели за темой не делается;
  - своя тема = свой набор: в /dict у слова «📂 → ✍️ Новая тема», дальше переносить туда слова из разных тем;
  - /dict: кнопка «🤖 Разложить «Разное» по темам» (видна, пока в «Разном» есть слова): модель раскладывает по 40 слов
    за запрос (`RELAYOUT_CHUNK`), `db.dict_move` — слово переезжает с прогрессом; что модель оставила в «Разном» —
    остаётся там.
- **Реализация (bot-pl):**
  - `bot/core/db.py`: колонка `dict_offers.topic` (`''` — авто), `offer_get` / `offer_save(..., topic)`,
    `dict_move(..., commit=True)`;
  - `bot/dictionary.py`: `offer_topic` (dp / dq), `offer_topic_text` (шаг `dict_offer_topic`), в `offer_done` и
    `dict_add_text(..., msg_id)` — `fixed` тема; `classify_topics(..., wait, topics)`, `dict_relayout` (dS);
  - `bot/ui/fmt.py`: `offer_topic_screen`, строка «📂 Куда» и кнопка «📂 Тема» в меню, `dict_buttons(topics, has_other)`;
  - `bot/app.py`: callback'и `dp:<msg>`, `dq:<msg>:<тема|0|->`, `dQ:<msg>`, `dS`, `dn:own:<msg>`; шаг
    `dict_offer_topic` в `TEXT_STEPS` (`bot/common.py`);
  - тесты `test_star_offer_own_topic_choice`, `test_dict_relayout_other_by_model_keeps_progress`.
- **Перенос в bot-en:** то же, `pl` → `en`, без транскрипции.

## S-015. 📖 Правило к нескольким пунктам упражнения из книги сразу

- **Где:** bot-pl, 2026-10-19.

- **Перенос в bot-en:** как есть (файлы те же).

## S-017. Пропадает DNS в Docker → бот молчит, «⏳ Проверяю…» висит

- **Где:** bot-pl, 2026-10-19. В логе: `getUpdates … httpx.ConnectError: [Errno -2] Name or service not known`
  каждые 5 с; помог перезапуск.
- **Причина:** на Windows с Docker Desktop после сна / смены сети ломается DNS внутри Docker; бот не может ни проверить
  ответ, ни написать об ошибке.
- **Решение (не сделано, BACKLOG, высокий):** A — бот сам завершается после ~5 мин без связи с Telegram (Docker
  поднимает по `restart: unless-stopped`); B — сторож в Планировщике Windows по heartbeat-файлу: интернет хоста →
  перезапуск контейнера → перезапуск Docker Desktop (`wsl --shutdown`) → сообщение в Telegram; общий для всех ботов.
  Плюс бот запоминает неотправленный ответ и после восстановления пишет «был сбой, пришли ещё раз».
- **Перенос:** одно решение на оба бота (и notes-bot).

## S-018. ⭐ В словарь из любого раздела + падеж в скобках + 🛡 защита от дублей

- **Где:** bot-pl, 2026-10-23, по запросу Марка.
- **Как работает:**
  - кнопка «⭐ В словарь» под результатом упражнения из книги (кроме tf / free), упражнения бота (в т. ч. карточки /

  - слово сохраняется В ТОЙ ФОРМЕ, как в ответе; не именительный — с пометкой падежа у слова и перевода:
    «kawę (B.) — кофе (вин.)»; форма, перевод слова и тема — один запрос `norm_prompt` (low). В наборе — «кофе (вин.)»;
  - 🛡 дубли (везде: меню, «✅ Готово», /dict add): слово в той же форме уже есть — не добавляется; в меню ⭐ с
    «уже в «<тема>»», нажатие — экран слова (первой кнопкой «📂 В мою тему», если в меню выбрана своя тема);

- **Перенос в bot-en:** без падежей (в английском их нет) — пометку формы можно взять для времени глагола / мн. числа
